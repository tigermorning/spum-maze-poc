# spum-maze-poc

SPUM Studio 만으로 **걸어 다닐 수 있는 공간**을 만들 수 있는지 재 본 기술 PoC.
Claude 가 Playwright 로 실제 Studio(`spum.soonsoon.ai/studio`)를 조작했다.
게임도, SAM 도, 별도 캔버스 미로도 없다. `sam-npc-core` 와 무관하다.

## 픽셀 측정만으로는 확정하지 못했던 이유 (기록)

세 번 측정했다(각 1~2분, 캔버스 픽셀에서 캐릭터 위치를 읽어 우리 벽 지도와 대조):

- 1차: 15칸 이동, 벽 칸 **0**
- 2차: 18칸(전이 27회), 벽 칸 **0**, 인접하지 않은 이동 1회(표본 간격 탓)
- 3차: 19칸, 벽 칸 **1** — 맨 위 테두리 (22,0)

측정의 한계가 남는다:

1. **런타임이 캐릭터 좌표를 내놓지 않는다.** DOM 에도 전역에도 없다. Transform 패널의 `pos` 는
   *배치값*이지 실시간 위치가 아니다. 그래서 캔버스 픽셀로 잰다.
2. **발 위치 기준점이 ±0.2칸 흔들린다** (스프라이트 아래끝에 이름표·말풍선이 섞인다).
   경계 칸에서는 한 줄 오차가 날 수 있고, 3차의 벽 1회는 정확히 그 경계(맨 윗줄)다.
3. **봉인 시험이 무산됐다.** 캐릭터를 벽으로 둘러싼 방에 가두려 했으나, 맵을 고치고 새로
   고치면 런타임이 캐릭터를 **다른 칸으로 옮겨 놓는다**(배치값 (5,15) → 실제 (9,14)).
   가둔 상태에서 출발시킬 수가 없었다.
4. **조작할 방법이 없다.** SPUM Link 로 배포한 World Viewer 는 재생 전용이라 방향키를 안 받는다.
   "벽 쪽으로 밀어 본다"를 사람이 하듯 시킬 수단이 없어, 자율 배회를 관찰하는 것이 전부다.

그래서 관측 대신 **런타임 소스를 따라갔다** — `EVIDENCE.md` 에 obstacle 레이어부터
A* 의 벽 칸 배제까지 줄 번호로 적었다. 남은 한계는 하나뿐이다:
**칸 좌표를 읽는 공개 API 가 없어**, 차단을 "거부 이벤트"로 실측하지는 못했다.

## 확인된 SPUM 사실

- 맵의 통행 표현은 **레이어 두 장**이다: `walkable`(1=걷기 가능)·`obstacle`(1=막힘). 서로 겹치지 않는다.
- 벽 타일은 테마의 `category:'obstacle_blocking'`, `movement:'blocked'` (기본 테마에 10종).
  `blocksMovement` 플래그는 이 테마에서 전부 false 라 **믿을 값이 아니다** — `movement` 를 봐야 한다.
- 맵은 라이브러리 SMO 를 직접 못 그린다. `tilesets[]` 에 `source:'map-theme'` 로 등록된 것만 그린다.
  **앱이 이미 구워 둔 테마를 복사하면** 손으로 만든 맵도 Map Editor 가 정상으로 그린다.
- **Map/World 편집기는 벽 칸에 캐릭터를 놓는 것을 막지 않는다** (되돌리지 않음).
- World 툴바의 **"베이크"는 내비게이션이 아니라 대화(BAKED CONVERSATION) 생성**이다.
- **SPUM Link 배포본은 재생 전용**이다 — 키 입력을 받지 않는다. 플레이어 조작이 필요하면 다른 길을 찾아야 한다.
- 공식 위키(`soonsoon2/SPUM/wiki`)에는 Studio·맵·충돌 문서가 **없다**(유니티 캐릭터 메이커 문서뿐).
  `soonsoon.co` 문서 사이트는 DNS 가 죽었다. 위 사실은 전부 앱을 직접 재서 얻었다.

## 남은 한계

런타임이 액터의 **칸 좌표를 공개하지 않는다**. `navAgent.state`·`destination`·`path` 는
내부에서만 돌고, 외부에는 Event Log 의 상태 문자열만 나온다. 그래서 "벽으로 밀었더니 거부됐다"는
이벤트 수준의 실측은 못 한다 — 차단은 소스 추적으로 확정했다.

## 1인칭 시야 시험 (`game/fp.html`)

**진짜 1인칭(3D·눈높이)은 SPUM 에 없다.** 엔진은 2D 스프라이트 톱다운이고, 카메라 성분이
가진 것은 `zoom` 과 `offset` 뿐이다 (`StudioSpumWorldRuntime.js:553-555`, `:3881-3893`).
공식 위키에는 Studio·카메라 문서가 아예 없다(유니티 캐릭터 메이커 문서뿐).

그래서 **네이티브로 가능한 가장 가까운 것**을 썼다: SPUM 자신의 카메라를 플레이어에 붙였다.
`rt.setViewport({ cssWidth, cssHeight, zoom, offsetX, offsetY })` 를 매 프레임 부른다
(`offsetX = 화면폭/2 - 플레이어x*zoom`, 소스의 `transform = (css/2 - offset)/zoom` 에서 뒤집은 것).
창 384×288, 배율 2 → 한 번에 **6×5칸만 보인다** (전체 25×19).

실측: 방향키 40회 이동 중 **벽 칸에 들어간 횟수 0**, 그중 7회는 벽을 향해 밀어 본 것이고 전부 막혔다.

## SPUM + SAM 통합 PoC (`game/play.html`)

미로 · 근접 추적 카메라 · NPC 둘 · SAM 대화를 한 화면에 붙인 것. 실제로 플레이해서 확인했다.

- **SPUM**: 이동은 `applyAIInteraction(moveToTile)` → 로코모션 → A*. 충돌은 obstacle 레이어(SPUM `runtimeGridForMap`).
  카메라는 `setViewport(zoom·offset)` 로 플레이어를 따라간다. 목적지는 맵의 `spawnPoints` 한 칸(막지 않는 네이티브 데이터).
- **SAM**: 대화는 `sam-npc-core` 프록시(`/api/sam/generate`)로만 간다. 인격은 `profiles/village/{ruby,mina}.json`
  을 그대로 읽고, 게임은 **길 안내 지식만** 얹는다(`knowledge.json`). 대사 트리 없음.
- 실측 플레이: (1,1) 출발 → 51걸음 걸어 미나 만남 → 자유 질문 → 동쪽 힌트 획득 → 루비 만남 →
  "남쪽은 막다른 길", "남동쪽 끝" 획득 → 잘못된 가지로 45걸음 들어가 막다른 길(3면 막힘) → 되돌아옴 →
  83걸음 걸어 (23,17) 목적지 도달. 벽 통과 0회.
- 알아 둘 것: **NPC 가 선 칸은 통행 불가**(런타임 점유 판정)라, NPC 는 경로 옆 곁방에 세워야 길이 막히지 않는다.
